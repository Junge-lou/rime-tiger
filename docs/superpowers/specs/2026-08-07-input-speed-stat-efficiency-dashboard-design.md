# 输入统计效率仪表盘设计

## 目标

扩展现有 `lua/input_speed_stat.lua`，在保留 `\tj` 菜单、跨窗口开关同步和 `tiger`/`tigress` 合并统计的前提下，增加毫秒级的击键、码长、打词率、回改、上屏方式、字词分布、编码分布和峰速数据。

统计范围统一为纯中文上屏。英文、数字、标点以及中英混合内容不进入字数、速度或新增指标。

## 参考与取舍

设计参考以下三类实现：

- `input_statistics_ms.lua` 的日/周/月/年、峰速、击键、码长和分布统计；
- 用户提供的空格/顶屏、回改和紧凑报表示例；
- `TypeSunnyPro` 的打词率定义。

不直接移植参考脚本。现有模块已经具备毫秒计时、统一数据文件、开关同步和 `\tj` 交互，扩展现有模块的回归风险更低。参考脚本通过输入串变化推测击键；本设计使用现有 processor 收集真实按键事件。

不引入参考脚本的 `/rtj` 命令、皮肤切换、名言和生字功能。

## 统计口径

### 纯中文

一次上屏文本中的每个 Unicode 码点都必须属于现有脚本支持的汉字范围，整次上屏才有效。只要包含英文、数字、标点或其他字符，本次上屏及其暂存按键全部丢弃。

### 上屏与字数

- `上屏`：有效纯中文 commit 的次数。
- `字数`：有效 commit 中的汉字总数。
- `单字`：commit 长度为 1。
- `打词`：commit 长度大于等于 2。

### 打词率

打词率与 TypeSunnyPro 一致，按汉字数而不是上屏次数计算：

```text
打词率 = 多字 commit 中的汉字数 / 全部有效汉字数 * 100
```

例如依次上屏 `你`、`好吗`、`我们`，总字数为 5，打词贡献字数为 4，打词率为 80%。

单字次数、打词次数另行保存。字词分布按 commit 次数计算，以免与按字数计算的打词率重复表达同一数据。

### 击键

击键统计真实发生的编码字符按键，包括随后被退格删除并重新输入的编码键；不包含退格键本身、修饰键、统计命令按键和选字/确认键。

报表中的 `击键` 为有效输入时段内每秒编码击键数，只显示数值，不附加单位：

```text
击键 = 编码击键数 / 有效输入秒数
```

### 码长

单次上屏码长为最终提交前的组合编码长度，不包含空格、回车、数字选字等确认键。周期报表中的 `码长` 为每字码长：

```text
码长 = 有效 commit 的最终编码长度总和 / 有效汉字总数
```

报表名称固定使用 `码长`，不使用“平均编码”等替代术语。

编码分布按每次 commit 的最终编码长度计数，固定展示 1 码、2 码、3 码、4 码和其他。

### 回改

回改只统计 processor 确实收到的退格按键。Esc 或无法确认的组合变化不推测为回改。

```text
回改率 = 回改次数 / 编码击键数 * 100
```

### 上屏方式

- `空格`：通过空格、回车或数字选字键完成的有效中文上屏。
- `顶屏`：没有上述确认键而自动完成的有效中文上屏。

两者按上屏次数计算占比，合计为 100%。字段内部使用 `manual_commit_count` 和 `auto_commit_count`，避免把回车或数字选字误解为物理空格键；报表沿用用户习惯显示为 `空格` 和 `顶屏`。

### 速度与峰速

- 所有时间使用 `rime_api.get_time_ms()`。
- 两次输入活动间隔超过 5000ms 时切断为新的有效输入段。
- 输入段至少持续 1000ms 才参与速度统计。
- 均速为周期有效字数除以有效输入时长，再换算为字/分钟。
- 峰速使用最近累计至少 10000ms 的滑动窗口；窗口同时记录对应的击键和码长。

## 数据模型

每个周期保存以下结构：

```lua
{
  commits = 0,
  chars = 0,
  seconds = 0.0,
  hit_count = 0,
  final_code_length = 0,
  backspace_count = 0,
  manual_commit_count = 0,
  auto_commit_count = 0,
  word_chars = 0,
  single_commit_count = 0,
  word_commit_count = 0,
  lengths = {},
  code_lengths = {},
  peak = { speed = 0, hit = 0, code_length = 0 },
}
```

周期包括日、周、月、年，并保留现有总计数据以兼容历史文件。`tiger` 和 `tigress` 继续共用 `lua/input_speed_stat_data.lua`。

旧文件缺少新增字段时补零，不清空已有字数和时长。新增周统计无法从旧的日/月汇总可靠反推，因此升级后从零开始累计；其他新增指标同样只统计升级后的输入。

## 事件流

1. processor 接收普通按键。忽略释放事件、修饰键和统计命令；把编码键、退格和确认键写入本次组合的临时状态。
2. update notifier 跟踪当前组合编码、输入起始毫秒和组合清空，保存最终码长所需的编码快照。
3. commit notifier 读取上屏文本并执行纯中文检查。
4. 非纯中文 commit 清空本次临时状态，不更新任何周期。
5. 纯中文 commit 按文本长度分类单字或打词，确定空格/顶屏，更新当前速度段及日、周、月、年、总计。
6. 统计关闭、方案切换、模块结束或 5000ms 空闲时结束当前速度段，并在需要时保存数据。

临时按键必须等到 commit 验证后才能入账，防止英文或混合上屏污染击键与回改数据。

## 报表与命令

保留现有命令入口：

- `\tjs`：当前或上次速度；
- `\tjj`：今日紧凑简报；
- `\tjx`：详细效率仪表盘。

今日简报示例：

```text
今日：上屏 95 次 · 输入 133 字
均速 76 · 峰速 108
击键 3.24 · 码长 2.56 · 打词率 55.6%
空格 88% · 顶屏 12%
回改 7 次 · 回改率 2.1%
```

详细仪表盘为今日、本周、本月、本年各提供一个候选，内容结构一致：

## 错误处理

- 数据文件不存在、字段缺失或旧版本结构不完整时使用默认值并继续运行。
- 单个数值不是有限非负数时归零，避免报表出现除零、`nan` 或 `inf`。
- 数据文件无法写入时保持内存统计，不中断输入；后续保存时重试。
- 日期滚动在读取报表和写入 commit 前执行，确保日、周、月、年边界正确。
- 临时组合状态在无效 commit、统计关闭和模块结束时清理，避免串入下一次输入。

## 测试

新增 Lua 测试覆盖：

- 单字、二字词、三字词的上屏次数、字数和 TypeSunnyPro 口径打词率；
- 字词分布按 commit 次数、打词率按字数计算的差异；
- 英文、数字、标点和中英混合 commit 完全不入账；
- 编码键、删除后重输、退格和最终码长的独立计数；
- 空格、回车、数字选字与自动顶屏分类；
- 5000ms 会话切断、1000ms 最小有效时长和 10000ms 峰速窗口；
- 日、周、月、年滚动以及 `tiger`/`tigress` 共用文件；
- 旧数据加载与新增字段补零；
- 简报和详细仪表盘的数值、固定标签及零数据输出。

运行仓库完整测试脚本，确认现有开关同步、方案配置和其他 Lua 功能没有回归。
